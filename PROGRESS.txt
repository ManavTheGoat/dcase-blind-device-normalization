The idea: train a lightweight residual CNN (DevNormNet, ~8K params) to map any
microphone's mel spectrogram toward a reference device (Device A) using paired
simulated device clips as supervision. At inference, apply blindly to unseen
real devices B and C — zero-shot device normalization.

  PROJECT OVERVIEW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Problem:
  Acoustic Scene Classification (ASC) models trained on professional microphone
  (Device A) degrade on consumer microphones (Devices B, C) due to device
  mismatch in frequency response. DCASE 2025 Task 1 highlights this — model
  must be <128K parameters and handle multiple devices.

Our contribution:
  1. We PROVE simple hand-crafted signal features (spectral centroid, rolloff,
     noise floor, flatness, HF ratio) CANNOT separate devices — scene content
     variance dominates (Figure 11: PCA shows complete mixing).
  2. We PROPOSE DevNormNet: a residual CNN trained on paired (Si, A) clips
     to learn and invert device-specific frequency distortions.
  3. We show transfer functions are consistent across scenes (learnable),
     unlike unstructured scene content noise (Figures 13, 14).
  4. At inference: DevNormNet is applied blind (no device label needed).

Dataset:
  TAU Urban Acoustic Scenes 2022 Mobile — 230,350 WAV clips, 10 scene classes,
  12 European cities, devices A/B/C/S1-S6 (simulated from A via known filters).
  Device A: 144,000 clips | S1-S6: ~10,800 each | B: 10,780 | C: 10,770
  Key insight: every Si clip has an EXACT Device A counterpart (same filename,
  different suffix) → perfect paired training data.

Paper title (working): "Blind Device Normalization for Low-Complexity Acoustic
  Scene Classification Using Simulated Device Pairs"
Target venues: DCASE 2026 Workshop (primary) / ICASSP 2027 (stretch)

  ARCHITECTURE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

DevNormNet (~8K params)  [src/normalization/devnorm.py]
  Input: mel spectrogram (1, 128, T)
  → Conv2d(1→8) + BN + ReLU
  → ResBlock × 2
  → Conv2d(8→1)   [residual connection: output = input + correction]
  Output: normalized mel spectrogram (same shape)
  Loss: L1 on mel-dB scale, trained on paired (Si, A) clips

CPMobile (~10K params)  [src/classifier/model.py]
  Input: normalized mel spectrogram
  → DepthwiseSeparableConv × 3
  → AdaptiveAvgPool2d(1)
  → Linear → 10 classes
  
Total pipeline: ~18K params (well under 128K DCASE limit)

  KEY TECHNICAL NOTES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

- AUDIO_DIR must be DATASET_ROOT (not DATASET_ROOT/audio/) because meta.csv
  and evaluation_setup CSVs store filenames as "audio/xxx.wav" already.
- PairedDataset base_key: strip "audio/" prefix, strip ".wav", then drop the
  last "-{device}" segment. Example: "audio/airport-lisbon-0-0-s1.wav" → 
  "airport-lisbon-0-0". Device A counterpart: "audio/airport-lisbon-0-0-a.wav"
- DevNormNet uses residual connection: output = input + learned_correction
  This is important — the network only needs to learn the delta, not reconstruct
  the full spectrogram from scratch.
- DCASE limit is 128,000 TOTAL parameters (DevNormNet + classifier combined).
  Our pipeline: ~8K + ~10K = ~18K. Plenty of headroom.
